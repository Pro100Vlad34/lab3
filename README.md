# Лабораторная 3 по дисциплине "Технологии программирования"

## Тема

Юнит-тестирование веб-приложения на Django.

За основу взят проект из лабораторной №2: интернет-магазин одежды с доработкой по индивидуальному заданию.

> **Вариант 10. Магазин одежды.**
> При одновременной покупке экземпляров товаров разного вида на общую сумму покупки предоставляется скидка 10%.

## Описание проекта

Проект: `tplab2`, приложение: `shop`.

Модели (`shop/models.py`):
- `Product` — товар: название, цена, категория (по умолчанию «Общее»);
- `Order` — заказ: покупатель, адрес, дата (ставится автоматически), итоговая сумма `total_price`;
- `Purchase` — позиция заказа, связывает заказ с товаром (у заказа позиции доступны через `order.items`).

Представления (`shop/views.py`):
- `index` — главная страница со списком товаров;
- `PurchaseCreate` — представление покупки одного товара (из исходной лабораторной);
- `checkout` — оформление заказа из нескольких товаров. Если в заказе есть товары из разных категорий, итоговая сумма уменьшается на 10%.

## Задание

Написать юнит-тесты для классов проекта, минимум по 2 теста на каждый класс.

## Что было сделано

### 1. Разбор имеющихся тестов

В проекте уже была папка `shop/tests/` с тремя файлами:
- `test_models.py` — класс `ProductTestCase`, 2 теста. В качестве данных использовались книги и канцелярия, а не одежда;
- `test_views.py` — класс `PurchaseCreateTestCase`, 1 тест (проверка доступности главной страницы);
- `test_checkout.py` — класс `CheckoutDiscountTests`, 3 теста на расчёт скидки.

Всего было 6 тестов. Для моделей `Order` и `Purchase` тестов не было, у `PurchaseCreate` был только один тест.

### 2. Приведение тестовых данных к теме магазина одежды

Во всех тестах товары заменены на одежду: «Футболка» и «Джинсы» (категория «Одежда»), «Кепка» (категория «Головные уборы»).

### 3. Добавление недостающих тестов

- добавлены классы `OrderTestCase` и `PurchaseTestCase` (по 2 теста);
- в `PurchaseCreateTestCase` добавлен второй тест, первый тест расширен;
- в `CheckoutDiscountTests` добавлены тесты на пустую корзину и на открытие страницы оформления.

Код самого приложения не менялся.

### 4. Запуск тестов

Тесты запускались локально на PostgreSQL, результат: **13 тестов, все OK**.

## Список тестов

### `shop/tests/test_models.py`

**ProductTestCase** — модель `Product`
1. `test_correctness_types` — у товара название имеет тип `str`, цена тип `int`.
2. `test_correctness_data` — цена и категория сохраняются в базе правильно.

**OrderTestCase** — модель `Order`
3. `test_default_total_price` — у нового заказа итоговая сумма по умолчанию равна 0.
4. `test_str` — дата заказа заполняется автоматически, строковое представление начинается с «Заказ от <имя>».

**PurchaseTestCase** — модель `Purchase`
5. `test_purchase_linked_to_order` — покупки привязываются к заказу и доступны через `order.items`.
6. `test_cascade_delete` — при удалении заказа удаляются и все его покупки.

### `shop/tests/test_views.py`

**PurchaseCreateTestCase** — представление `PurchaseCreate` и главная страница
7. `test_view_config` — представление работает с моделью `Purchase`, после покупки перенаправляет на `/`.
8. `test_webpage_accessibility` — главная страница отвечает кодом 200, использует шаблон `shop/index.html` и выводит список товаров.

### `shop/tests/test_checkout.py`

**CheckoutDiscountTests** — оформление заказа и скидка (индивидуальное задание)
9. `test_no_discount_same_category` — футболка + джинсы (одна категория): скидки нет, итог 3000.

13. `test_get_checkout_page` — страница `/checkout/` открывается и использует шаблон `shop/checkout.html`.

## Как запустить тесты

1. Установить зависимости:
   ```
   pip install -r requirements.txt
   ```
2. Запустить PostgreSQL (база `django_db`, пользователь `postgres`).
3. Задать пароль от пользователя `postgres` (PowerShell):
   ```
   $env:DATABASE_PASSWORD = "пароль"
   ```
4. Запустить тесты:
   ```
   python manage.py test shop/tests/
   ```

Для тестов Django сам создаёт временную базу `test_django_db` и удаляет её после завершения, рабочая база не затрагивается.

## CI

В репозитории настроен GitHub Actions (`.github/workflows/django.yml`). При push в ветки `master` и `discount`, а также при pull request в `master`, поднимается PostgreSQL и выполняются все тесты из `shop/tests/`.
